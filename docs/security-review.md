# Security review — 2026-11-06

Reviewed the local HTTP server, browser renderer, Codex JSONL reader, ChatGPT import and handoff, generated terminal commands, and npm package contents. The reviewed baseline was version 0.1.0, commit `efd410f`. Fixes are prepared for 0.1.1.

## Findings and fixes

| Finding                                                 | Prerequisites and impact                                                                                                                                                                                                                                     | Fix                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PowerShell command injection — high                     | A crafted working directory, profile path, or export path containing a smart apostrophe could terminate a quoted string when a user pasted the generated PowerShell command.                                                                                 | Escape ASCII apostrophes and all four Unicode single-quote delimiters recognized by PowerShell, using one shared quoting function.                                                                                                                                    |
| Access-key disclosure across localhost ports — moderate | After unlocking Playback, visiting another service on `127.0.0.1` could send the access cookie to that service. Cookie names containing a port do not restrict cookie delivery to that port. A service obtaining the key could then request private history. | Require an explicit bearer header on every API request; set no authentication cookies. The browser uses the private URL fragment, omits cookies on API fetches, and refuses redirects. Existing Host, Origin, cross-site, CSP, and cache protections remain in place. |
| Syntax-highlighting denial of service — moderate        | A transcript containing a long unterminated string with repeated escaped quotes caused quadratic regular-expression rescanning and could freeze the browser.                                                                                                 | Consume unterminated strings and block comments through the end of the code block, including trailing backslashes, without retrying from each embedded quote.                                                                                                         |
| Markdown-parser denial of service — moderate            | A code-fence header containing a carriage return or Unicode line/paragraph separator made the fence matcher reject a line that the paragraph matcher also refused to consume. Even a short message could trap the browser in an infinite loop.               | Accept all characters in fence headers and make the paragraph branch consume its first line unconditionally, guaranteeing forward progress.                                                                                                                           |
| Unsafe terminal characters in copied paths — hardening  | Shell quoting alone does not control how a terminal interprets pasted escape sequences or displays directional overrides.                                                                                                                                    | Refuse generated commands with control characters, Unicode line separators, or bidirectional control characters in path arguments. Conversation text and intentionally copied code remain unchanged.                                                                  |

PowerShell's quote handling is documented in [Microsoft's quoting rules](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_quoting_rules?view=powershell-7.5) and its [parser character definitions](https://github.com/PowerShell/PowerShell/blob/master/src/System.Management.Automation/engine/parser/CharTraits.cs). Cookie and origin boundaries are described in [MDN's same-origin policy documentation](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy).

## Regression checks

- Server tests require bearer authorization for list, transcript, refresh, and unlock routes. They verify no access cookie is issued, legacy cookies are rejected, and foreign origins and ports cannot bypass the checks.
- Client tests verify the fragment key is attached to API requests, cookies are omitted, and redirects are refused. Browser coverage checks reloads, locked tabs without the key, and credential-free navigation to another localhost port.
- Command tests cover all smart apostrophes in directory, profile, and ChatGPT export paths, plus terminal controls. A native PowerShell round-trip test runs when PowerShell is installed.
- The highlighting reproduction runs a 1 MB escaped unterminated string in a worker with a three-second limit. It timed out before the fix and completed in about 15 ms afterward on the review machine, preserving the source exactly.
- A separate worker checks both code-fence markers with carriage returns and Unicode line/paragraph separators. It timed out before the parser fix and rendered all six cases in about 12 ms afterward. The browser suite also includes a separator in a code-fence header.
- Existing coverage checks inert HTML/script content, safe POSIX quoting, discovered-ID access, symlink rejection, selected export branches, and private handoff-file cleanup.

## Verification limits

The build and strict TypeScript checks passed. The local test suite completed with **49 passed, zero failed, and three skipped**: two loopback-listener checks blocked by the sandbox and the native PowerShell test. The maintainer subsequently ran the expanded browser suite in a normal terminal and reported **one passed, zero failed, and zero skipped**, including the new authentication and malformed-fence regression checks.

The two live-server checks still need a normal-terminal `npm test` run. PowerShell is not installed on the review host, so native execution needs a host with `pwsh` or Windows PowerShell; quoting cases are covered by the portable tests and checked against the upstream parser.

The sandbox's `npm audit` request failed because DNS resolution for `registry.npmjs.org` was blocked. The maintainer subsequently ran `npm audit` from a normal terminal against this checkout and reported **zero vulnerabilities**. The package has no runtime dependencies, and no dependencies were changed during this review. The advisory scan covers known dependency issues; the source-code findings above require their own fixes and tests.

Playback remains a local tool. It does not protect history from processes running as the same OS user, browser extensions with access to the page, or a compromised machine. Very large local history and export files can still consume substantial memory. Keep the full launch link private, avoid exposing its port, and restart the app after installing the patched release.

## Follow-up: Safari startup compatibility in 0.1.2

Version 0.1.1 forced Fetch's `same-origin` request mode while sending `Referrer-Policy: no-referrer`. For non-GET requests that mode can redact the Origin header to `null`, causing the strict server check to reject startup and refresh POST requests. Changing the archive filter issues GET requests, explaining why the interface could recover afterward. This follows the [Fetch standard's Origin-header algorithm](https://fetch.spec.whatwg.org/#append-a-request-origin-header).

Version 0.1.2 uses the default `cors` request mode with the same relative local API URLs. Host and Origin validation, bearer authentication, no-referrer, omitted cookies, redirect refusal, and the self-only connection policy remain enforced; the server still rejects `Origin: null` and foreign origins. No CORS allowance is added.

The regression test models browser Origin serialization before calling the real HTTP handler. It failed with the original client settings and passes with the corrected mode. A separate browser test uses actual HTTP requests for startup and refresh, checking their final Origin and Referer headers. It can also run in WebKit. The earlier browser suite used request interception and Chrome; it did not check this behavior over a real HTTP connection or in WebKit.

The maintainer confirmed that the patched application loads projects immediately in Safari without opening or changing filters, and reported **both automated browser checks passing** in a normal terminal for 0.1.2. The local suite completed with **50 passed, zero failed, and three skipped** for unavailable loopback or PowerShell execution. Native PowerShell execution remains unverified on this host.
